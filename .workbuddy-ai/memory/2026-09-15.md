Dilakukan analisis menyeluruh pertama atas repo `schoolerp`. Temuan utama:

### Fakta proyek
- Monorepo decoupled: `backend/` (Laravel 13.31, PHP 8.4.11) + `frontend/` (React 18 + TS 5.7 + Vite 6) + `docs/`
- DB: MySQL 9.4, database `syntaf_school`. Test pakai SQLite in-memory (`phpunit.xml`)

- LOC: backend app+routes+database = 3.797; frontend src = 4.937
- Verifikasi: `php artisan test` → **8 passed / 16 assertions**; `npx tsc --noEmit` → **0 error**

### Pola arsitektur kunci (penting untuk kerja selanjutnya)
- **Config-driven CRUD**: satu `MasterDataController` + satu `config/master_data.php` melayani 40 resource via route `/master/{resource}`. Frontend mirror-nya `frontend/src/constants/masterData.ts` + `MasterDataPage.tsx`.
- Registry master data **diduplikasi manual** antara PHP dan TS — tidak ada codegen, jadi setiap penambahan resource harus diubah di dua tempat.
- `ApiResponse` trait → format respons konsisten `{success, message, data, meta}`.
- RBAC: spatie/laravel-permission, guard `web` (dipaksa via `User::getDefaultGuardName()`), 10 role / 12 modul / 47 permission.
- Halaman modul belum dibangun memakai `ModulePlaceholderPage`.

### Masalah yang ditemukan (belum diperbaiki)
1. **Tidak ada repositori Git** sama sekali (tidak ada `.git`, tidak ada `.gitignore` di root). Risiko tertinggi.
2. **Whitelist `filter` di `config/master_data.php` tidak ditegakkan** — `MasterDataController::index()` menerapkan `where($column, $value)` langsung dari query string tanpa cek `$config['filter']`. `sort` sudah divalidasi, `filter` tidak.
3. **Cakupan test tipis**: hanya `RbacTest`. `MasterDataController` (inti 40 resource), akademik, kelas, siswa belum ada test.
4. **Dokumen usang**: docs menyebut Laravel 11 / PHP 8.2+ / port 8000; aktual Laravel 13.31 / PHP 8.4 / 8001. `README.md` masih bilang "tahap perencanaan selesai".
5. `backend/.env` ikut ada di working tree (berisi `APP_DEBUG=true`, `DB_PASSWORD` kosong).
6. `npm run lint` ada di `package.json` tapi **tidak ada config ESLint**.
7. `backend/AGENTS.md` dan `backend/CLAUDE.md` identik (duplikat).
8. `StudentController` & `EmployeeController` hanya punya `index()` (read-only lookup), belum CRUD, padahal tabelnya lengkap.
9. Tidak ada dokumentasi API (Scribe/OpenAPI) — masih item Fase 6.
10. `docs` menyebut 41 tabel master data, aktual 40 resource.

## Penyusunan breakdown Fase 2 (lanjutan)

Dibuat **`docs/05-PLAN-FASE-2.md`** — breakdown Fase 2 yang dipecah jadi sub-fase 2A–2E
karena Fase 2 memuat banyak menu. Sekaligus diperbarui `README.md` (tabel dokumen) dan
bagian Fase 2 di `docs/PROGRESS.md` (sebelumnya salah menandai periode akademik & kelas
sebagai belum selesai, padahal sudah jadi).

### Isi rencana
- **2A Kepegawaian dasar** — CRUD Data Pegawai + `EmployeeSeeder`
- **2B Kesiswaan dasar** — Data Siswa (form stepper, dropdown wilayah berjenjang) + Wali Murid (aturan satu `is_primary`) + `StudentSeeder`
- **2C Akademik lanjutan** — Mapel per Kelas (`class_subjects`) → Jadwal Pelajaran (`schedules`) dengan 4 validasi bentrok: kelas, guru, ruangan, jam terbalik
- **2D Proses & catatan siswa** — Kenaikan Kelas & Mutasi (`student_histories`, wajib transaksi + pratinjau), Pelanggaran & Poin, Prestasi, Ekstrakurikuler
- **2E Opsional** — Absensi Pegawai, Beban Mengajar Guru, Riwayat Jabatan

### Temuan penting saat menyusun rencana
- **Urutan ketergantungan kritis**: `employees` dan `students` belum punya seeder sama sekali
  → tabel kosong. Menu Akademik lanjutan (wali kelas, guru pengajar) buntu tanpa Data Pegawai,
  jadi 2A harus jalan lebih dulu. Ini masuk akal secara teknis, bukan sekadar preferensi.
- **6 tabel baru** dibutuhkan: `student_histories`, `student_violations`, `student_achievements`,
  `student_extracurriculars`, `employee_attendances`, `employee_positions`.
- **Permission tidak perlu ditambah** — `academic.*`, `student.*`, `employee.*` sudah tersedia
  di `RolePermissionSeeder` (opsional: `academic.promote` bila ingin memisahkan hak kenaikan kelas).
- Keputusan desain yang dicatat di dokumen: menu Fase 2 yang kompleks (siswa, jadwal) **jangan**
  dipaksa masuk pola generik `MasterDataController` — pakai controller & halaman khusus.

## Eksekusi 2A — Data Pegawai (SELESAI)

### Keputusan user
- **Database dev dipindah dari MySQL ke SQLite** (`backend/database/database.sqlite`).
  `.env`: `DB_CONNECTION=sqlite`, `DB_DATABASE=<path absolut>`, baris MySQL dikomentari.
  `/database/*.sqlite` ditambahkan ke `backend/.gitignore`.

### Temuan penting saat migrasi ke SQLite
- Migrasi `2026_09_15_100001_create_academic_core_tables` ternyata masih **Pending** di MySQL —
  artinya tabel `employees`/`students`/`school_classes` belum pernah dibuat di DB dev.
  Setelah pindah ke SQLite, migrasi ini baru benar-benar jalan.
- File `database.sqlite` **sudah ada sebelumnya** dengan skema `users` versi usang
  (tanpa `username`, `is_active`, `deleted_at`) sehingga `UserSeeder` gagal
  (`no such column: users.deleted_at`). Migrasi di file itu tercatat `[1] Ran` sehingga dilewati.
  **Solusi:** `php artisan migrate:fresh --seed` — aman karena `users` berisi 0 baris.
- Jadi: kalau ada error "no such column" pada SQLite, curigai file DB yang lebih tua dari migrasi,
  bukan migrasi yang salah.

### Yang dibangun
**Backend**
- `app/Http/Requests/Employee/EmployeeRequest.php` — validasi + `attributes()` Indonesia
- `app/Http/Resources/EmployeeResource.php` — termasuk `homeroom_classes_count`, `class_subjects_count`, `has_account`
- `app/Http/Controllers/Api/EmployeeController.php` — index/show/store/update/destroy/toggleActive/createAccount
- `app/Models/Employee.php` — tambah relasi `user()` morphOne ke `User`
- `routes/api.php` — 7 route `/employees` dengan `permission:employee.*`
- `database/seeders/EmployeeSeeder.php` — 10 pegawai (8 guru, 2 staf), didaftarkan di `DatabaseSeeder`
- `tests/Feature/EmployeeTest.php` — 12 test / 30 assertion

**Frontend**
- `src/types/index.ts` — `Employee`, `EmployeePayload`, `EmployeeQueryParams`, `EmployeeAccountPayload`
- `src/features/employees/api/employeesApi.ts`
- `src/features/employees/components/EmployeeFormModal.tsx`
- `src/features/employees/pages/EmployeesPage.tsx`
- `src/routes/index.tsx` — route `/employees` menggantikan placeholder

## Sesi lanjutan — A2 Jadwal Pelajaran (selesai)

Tahap **A2** dari `docs/06-BLUEPRINT-AKADEMIK.md` §8 dikerjakan penuh: jam pelajaran,
jadwal mingguan, 4 deteksi bentrok, dan perubahan jadwal harian.

### Backend
- Migrasi `2026_09_15_110001_create_time_slots_and_schedule_changes_tables.php`
  - `time_slots` — jam pelajaran per hari; unik `(day_id, slot_number)`
  - `schedule_changes` — guru pengganti / pindah / batal; unik `(schedule_id, date)`

  relasi `timeSlot()`/`changes()` + scope `forSemester()`/`overlapping()`
- Resource `TimeSlotResource`, `ScheduleResource`, `ScheduleChangeResource`
- `TimeSlotController` — CRUD + `generate` template + validasi tumpang tindih jam & nomor jam unik
- `ScheduleController` — CRUD + `check-conflict` + `grid` + `indexChanges`/`storeChange`/`destroyChange`
- 12 route baru; `permission:academic.*`
- `TimeSlotSeeder` — 47 jam pelajaran (Senin–Kamis 8 JP 45 menit, Jumat 6 JP 40 menit)

### Empat deteksi bentrok (inti A2)
Dikumpulkan oleh `ScheduleController::detectConflicts()`, lalu dilempar sebagai
`ValidationException` ke field yang tepat:

| Aturan | Field error | Cara uji |
|--------|-------------|----------|
| 1. Bentrok **kelas** | `start_time` | mapel lain di kelas sama, jam beririsan |
| 2. Bentrok **guru** | `employee_id` | kelas lain, guru sama, jam beririsan |
| 3. Bentrok **ruang** | `room_id` | kelas & guru lain, ruang sama, jam beririsan |
| 4. **Jam terbalik** | `end_time` | `end_time <= start_time` |

Irirsan dihitung `start_time < end AND end_time > start` → **jam bersebelahan (07:45 setelah 07:45)
bukan bentrok**; ada test khusus untuk batas ini.

Aturan pendukung: mapel wajib sudah ada di `class_subjects` kelas tersebut; guru wajib `is_teacher`;
`time_slot_id` harus milik hari yang sama; guru pengganti tidak boleh sedang mengajar di jam itu
(dicek dengan `Carbon::parse($date)->dayOfWeekIso`).

### Frontend
- `schedulesApi.ts` (jadwal + jam pelajaran + perubahan), tipe di `types/index.ts`
- `SchedulesPage.tsx` — grid mingguan, kolom per hari (bukan matriks kaku, karena jumlah jam
  Jumat berbeda), sudut pandang per kelas/guru/ruang, input tanggal untuk melihat perubahan harian
- `ScheduleFormModal.tsx` — peringatan bentrok **langsung** (debounce 400 ms ke `check-conflict`)
- `TimeSlotsModal.tsx` — kelola jam pelajaran + isi dari template

- Data dev: 47 jam pelajaran, 39 `schedules` (kelas 1 penuh 38, kelas 2 1), 41 `class_subjects`

### Jebakan baru yang ditemukan
1. **`HTTP_PROXY`/`HTTPS_PROXY` aktif di environment shell.** `curl`/`urllib` ke `127.0.0.1:8001`
   lewat proxy → balasan **502**, dan `curl` tetap exit 0 sehingga probe "server siap" lolos prematur.
   **Solusi:** `curl --noproxy '*'` dan jalankan python dengan
   `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy`.
2. **Dua `Edit` ke file yang sama dalam satu pesan saling menimpa.** Keduanya membaca isi lama lalu
   menulis, sehingga hasil edit pertama hilang. Jalankan edit berurutan untuk file yang sama.
3. `php artisan route:list` melempar `ReflectionException: Class "X" does not exist` bila
   `use` statement controller baru belum masuk ke `routes/api.php` — pesan error menunjuk
   `RouteListCommand`, bukan akar masalahnya.
4. Model baru kadang belum ter-autoload → jalankan `composer dump-autoload` setelah menambah controller/model.

### Dua bug nyata yang ditemukan & diperbaiki
1. **Guest request tanpa `Accept: application/json` → 500, bukan 401.** Laravel 11 default
   `redirectGuestsTo(fn () => route('login'))`, sedangkan SPA ini tidak punya route `login`.
   Diperbaiki di `bootstrap/app.php` dengan override yang mengembalikan `null` untuk `api/*`.
   Ini menutupi semua 401 asli bagi klien non-axios.
2. **`destroyHistory()` tidak menghapus keanggotaan rombel** yang dibuat oleh `storeHistory()`.
   Akibatnya `class_students` menjadi data yatim dan siswa **tidak akan pernah bisa dihapus**
   (pesan errornya menyesatkan: "masih terdaftar pada rombel"). Sekarang simetris, dan ada 2 test
   yang menjaga perilaku ini.

### Kebersihan
- **`routes/api.php` dirapikan** — blok `time-slots`/`schedules` terduplikasi (sisa insiden edit
  paralel di A2) dihapus. File ditulis ulang bersih.
- Route `students` dipindah keluar dari seksi RBAC ke seksi Kesiswaan.
